## 当前交付边界

本轮删除后台 Memory 种子全链，保留同作者及时快路，接通原队列后台复核及有限外推，
并向已有真人焦点的 Jev 请求附带 Yuki 自身参与意愿。普通接纳、SELF 机会、Work 与真实效果继续分开。
主 Agent 仍按需查记忆、使用原工具、发送或 NO_REPLY；没有第二个 Runner、发送配额或状态驱动的补问。

## 必须保持的边界

1. Host 提供已入账、已授权的内部来源。语义对象不是执行主体，平台消息 ID 不重建所有权。
2. 观察对应原 scope、焦点、版本和请求序号。context 只用于解释，不批量算已评分或已确认快接。
3. 真实撤回/修订仍撤销来源；意愿更新不 veto 在途结果，也不清空群历史或重跑模型。
4. 原 proposal 接纳未知先查原 ID；原已接纳 Work 按原预算、执行和回执续跑，不盲目重发。
5. epoch 约束新接纳，generation 与真实授权继续约束原执行；迟到真实效果可入账，不能复活终态。
6. 固定 Main 工具与统一出口由 Host 保持；本库不修改工具声明、QQ 发送权限或 Provider 路由。
7. 新接纳事务不等模型/网关、不扫描历史；SnapshotStore 不跨线程共用连接。
8. 前向升级保原事实；有新输入/效果后回退采用兼容修复版本，不用旧数据库覆盖新事实。

## 工程参数与离线验证

原详细事件窗口为 600 秒、256 条及 256 KiB；它是 replay 资源边界，不是互动关系自动过期。
原观察队列最多 64 个焦点，同源修订合并；活跃 2/8/15 秒、非活跃 3/12/20 秒分别为去抖/最小间隔/最长等待，
不是固定模型周期。未评分 conversation 在源事件后 75 秒到期；合格观察在源事件后 90 秒内完成，
支持到 min(源事件+150 秒，完成+75 秒)。优先级不绕过间隔，也不产生授权。

快照默认每 scope 1 MiB、总计 16 MiB，参与单元/来源身份沿原资源界限整理。
quiet/closed 保留查询事实，Host 的活跃档消费者排除它们；新状态元数据不排额外请求。
三个种子参数退役，其余真实覆盖保留；默认跨度 4 复用原热参数，不重置历史计数、预算或已接纳 Work。

[有限快路报告](evidence/fastpath-review-replay-2026-10-15.json)包含 192 条 active/inactive 队列对照。
Controller/队列是真实实现，语义标签为合成，tick 为虚拟 2 秒；
五份已有真实请求耗时提供约 6 秒量级，未新增付费请求。
每条轨迹输入 90 秒，再排空 22 秒，总窗口 112 秒，报告调用数必须使用这个完整窗口。

选择 K=4 时，active 的 5 秒输入间隔正向轨迹保留 18/18 次快接，inactive 对照为 16/18；
它同时限制未确认换题后的继续外推。更大跨度可增加高密度快接，也增加尚未纠正时的外推。
这不是生产最优参数、真实 Main 延迟、独立语义准确率或净成本节省。

定向回归覆盖同时间 hint 双向排序、opaque ID 的迟到负反馈、新确认只覆盖原进度、
quiet 不被旧正结果/真实发送复活、重复 hydrate/恢复不重复计数、旧未知进度与正文裁剪，
以及实际 ObservationSession timeout/退避重排/冷恢复不补确认。
合成 unknown 与实际抛 timeout 分别测试，不把前者冒充传输故障。
库的整套测试数、Ruff/Mypy、CI 与 Host 安装联测以该修订实际运行结果记录，不继承旧版 179 通过的数字。

Host 还须核原接纳、防重、原 Work/Presence、私有资料、上下文装配、统一出口与真实缓存 usage。
当前测试不访问主模型或 QQ，不能证明用户实际感到少刷屏、模型更准确或生产已经载入新参数。
